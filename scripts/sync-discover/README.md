# sync-discover

Syncs the real "figures" (curated readers) and their book recommendations from Readen's production Supabase project into a checked-in static snapshot at `src/content/discover/`. The site reads this snapshot from the filesystem at build time (`src/lib/figures.ts`) — this script is a manual, occasional tool, **not** part of the build pipeline. `lp` makes no live backend calls at build or runtime.

## Quick start

```bash
export NEXT_PUBLIC_SUPABASE_URL=https://qksmdkcxwljszptmykyj.supabase.co
export SUPABASE_ANON_KEY=<the project's anon/publishable key>

bun run sync:discover
```

Both env vars can also live in a local `.env` (bun loads it automatically) — see `.env.example` at the repo root.

Only a read-only anon key is needed: `figures`, `books`, `book_figure`, `authors`, `book_author`, `industries`, and `figure_industry` are all public-read tables. No service-role secret is required or should be used here.

## What it does

1. Fetches `figures`, `books`, `book_figure`, `industries`, `figure_industry`, `authors`, `book_author` from Supabase, paginated in batches of 1000.
2. Dedupes books (a book can be recommended by multiple figures), resolves author names, resolves industry names, computes each figure's `recommendationCount`.
3. Drops any figure with zero recommended books (defensive — not expected given current data).
4. Sorts figures by `recommendationCount desc, name asc` (deterministic — this order is what `/discover` pagination uses, unchanged until the next sync).
5. Writes `src/content/discover/figures.json`, `books.json`, and `industries.json`.

## When to re-run

Whenever the app's figures/books/recommendations catalog changes and you want the marketing site's `/discover` section to reflect it. Re-running is idempotent — the same source data always produces byte-identical output.

## Bio enrichment (`bios.json`) — separate, manual step

`figures.json`'s `bio` field is the raw scraped blurb from the source (English only, and often close to text already published elsewhere — weak for SEO). `src/content/discover/bios.json` is a **separate, hand-curated overlay**: for each figure, a rewritten English bio (same facts, original wording) plus real Spanish and Portuguese translations, used instead of the raw `bio` wherever a figure page renders content (`src/lib/figures.ts`'s `getFigure(slug, locale)` resolves `bios.json` first, falling back to the raw `bio` if a slug has no entry yet).

This file is **not generated by `sync.ts`** — there's no LLM API wired into this script. It was produced by asking Claude to rewrite + translate each figure's bio (batched, in a Claude Code session) and merging the results into `bios.json`. After adding new figures via a re-sync, run the same process for just the new slugs (anything missing from `bios.json` silently falls back to the raw English `bio`, so this is safe to leave stale for a while — just weaker for `/es` and `/pt` SEO until it's refreshed).
